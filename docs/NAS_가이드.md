# 대산 Wiki 프로젝트 — NAS 연동 가이드

이 문서는 Wiki LLM 프로젝트(`daesan-wiki-sync`)를 Synology NAS(`DaesanNAS`, ds3648)와 연동해서, 여러 대의 컴퓨터에서 같은 위키 자료를 보고/수정할 수 있게 만드는 전체 과정을 정리한 것입니다.

---

## 1. 전체 구조 한눈에 보기

```
[본인 로컬 컴퓨터 A] ← 인제스트 담당
   ↓ Wiki LLM 앱이 소스를 분석해 entity/concept 생성 (로컬 디스크에 직접 저장)
   ↓ Synology Drive Client가 변경 감지 → 자동 업로드
[NAS: 성장전략실/Wiki_시장]  ← 항상 최신 상태를 유지하는 기준 저장소
   ↓ Synology Drive Client (양방향 동기화)
[다른 컴퓨터 B] ← 보기 + 수정
   ↓ B가 수정하면 자동으로 NAS에 반영 → A에도 자동으로 내려옴
```

- NAS가 "항상 최신 버전이 있는 단일 기준점" 역할을 합니다.
- 누가 어디서 수정하든 자동으로 양쪽에 반영되고, 다음 인제스트는 그 최신 상태를 기반으로 지식을 쌓아갑니다.
- 단, **동시에 같은 파일을 여러 명이 건드리면 충돌**이 생길 수 있으므로 아래 "협업 원칙"을 반드시 지켜야 합니다.

---

## 2. 프로젝트 폴더 구조

```
daesan-wiki-sync/
├── purpose.md      ← 프로젝트 목적 정의
├── schema.md         ← 엔티티/컨셉 스키마 정의
├── raw/              ← 원본 소스 파일 (raw/sources/)
├── wiki/              ← 생성된 지식 콘텐츠
│   ├── entities/       - 구체적 대상 (브랜드, 자재유형, 사례 등)
│   ├── concepts/        - 패턴/인사이트 (트렌드, 클레임패턴, SEO키워드 등)
│   ├── synthesis/        - 여러 엔티티/컨셉을 종합한 결론
│   ├── sources/           - 소스별 요약 페이지
│   ├── queries/            - 채팅에서 저장한 답변
│   └── comparisons / findings / thesis / methodology/
└── .llm-wiki/         ← (숨김) 인제스트 큐 상태, 리뷰/중복판단 이력, 채팅기록, 캐시
```

`wiki/`, `raw/`, `.llm-wiki/` 전부 있어야 완전한 프로젝트입니다. 하나라도 빠뜨리고 옮기면 리뷰 상태나 큐 정보가 유실될 수 있습니다.

---

## 3. 로컬 경로가 iCloud에 있으면 안 되는 이유

iCloud Drive는 "로컬에 있는 것처럼 보이지만 실제로는 필요할 때만 다운로드"하는 지연 동기화 구조입니다. 그래서:
- 파일이 있는 것처럼 보이지만 실제로는 아직 안 받아져서 인제스트 중 읽기 실패가 날 수 있음
- Synology Drive와 이중으로 클라우드 동기화가 겹치면 두 서비스가 서로 "내가 최신이다" 하며 충돌할 위험이 있음

**따라서 반드시 일반 로컬 폴더(예: `~/Documents/`)로 옮긴 뒤 NAS와 연동해야 합니다.**

### iCloud → 로컬로 옮기는 명령
```bash
mkdir -p ~/Documents/daesan-blog-wiki
cp -R "iCloud 경로/." ~/Documents/daesan-blog-wiki/
```
복사 후 파일 개수를 원본과 비교해서 누락이 없는지 확인:
```bash
find "iCloud 경로" -type f | wc -l
find ~/Documents/daesan-blog-wiki -type f | wc -l
```
두 숫자가 같으면 안전하게 옮겨진 것입니다.

## 4. 본인(A) 컴퓨터 — NAS 쓰기 담당 설정

### 4-1. Synology Drive Client 설치
- Synology 홈페이지 → 다운로드 센터 → NAS 모델 검색 → **Synology Drive Client** 다운로드/설치

### 4-2. 로그인 시 자주 나는 에러: "잘못된 사용자 이름/패스워드 또는 사용자 권한이 충분하지 않습니다"

이 에러가 뜨면 아래 순서로 원인을 좁혀갑니다.

| 순서 | 확인할 것 | 위치 |
|---|---|---|
| 1 | DSM 웹 로그인 자체가 되는지 (비밀번호 검증) | 브라우저로 DSM 로그인 시도 |
| 2 | 해당 계정에 Synology Drive 앱 사용 권한이 켜져 있는지 | 제어판 → 사용자 및 그룹 → 계정 선택 → 응용 프로그램 탭 → Synology Drive 허용 체크 |
| 3 | Synology Drive Server 패키지가 설치·실행 중인지 | 패키지 센터 → 설치됨 → Synology Drive Server |
| 4 | **"Synology 응용 프로그램 서비스"가 최신 버전인지** (실제 원인이었던 경우) | 패키지 센터 상단 "업데이트 사용 가능" 목록에서 업데이트 |
| 5 | 사용자 홈 서비스가 켜져 있는지 | 제어판 → 사용자 및 그룹 → 고급 → "사용자 홈 서비스 활성화" |

> 실제 사례: 위 1~3번은 모두 정상이었는데, **4번(Synology 응용 프로그램 서비스 업데이트)**을 적용하고 나서 로그인이 해결됨.

### 4-3. 동기화 작업 생성 시 주의사항 — "폴더 경로에 이름이 자동으로 덧붙는 문제"

Synology Drive Client는 "로컬 폴더"와 "작업 이름" 필드가 서로 연동되어 있어서, 한쪽을 나중에 고치면 다른 쪽 값을 참고해 경로를 재조합합니다. 그래서 **이미 있는 폴더를 그대로 지정하려 해도, 폴더 이름 뒤에 작업 이름이 하위 폴더처럼 자동으로 붙어버리는 현상**이 발생할 수 있습니다.

**해결 방법 (실제로 작동한 방법)**
1. 일단 앱이 자동으로 만드는 대로 진행 (`완료`) — 예: `daesan-blog-wiki/daesan-wiki-sync`라는 새 빈 폴더가 생성됨
2. Drive Client에서 해당 동기화 작업을 **일시정지**
3. 터미널에서 기존 프로젝트 파일들을 그 새로 생긴 폴더 "안으로" 이동
   ```bash
   mv ~/Documents/daesan-blog-wiki/wiki ~/Documents/daesan-blog-wiki/daesan-wiki-sync/
   mv ~/Documents/daesan-blog-wiki/raw ~/Documents/daesan-blog-wiki/daesan-wiki-sync/
   mv ~/Documents/daesan-blog-wiki/.llm-wiki ~/Documents/daesan-blog-wiki/daesan-wiki-sync/
   mv ~/Documents/daesan-blog-wiki/purpose.md ~/Documents/daesan-blog-wiki/daesan-wiki-sync/
   mv ~/Documents/daesan-blog-wiki/schema.md ~/Documents/daesan-blog-wiki/daesan-wiki-sync/
   ```
4. Drive Client에서 동기화 **재개**
5. 이후 Wiki LLM 앱에서 프로젝트를 열 때는 새 경로(`~/LLMWiki/daesan-wiki-sync`, 2026-11-20 이동 후 현재 경로)를 사용. 위 1~5단계는 2026-11-20 이전 절차 기록이다.

### 4-4. 참고 — `find` 명령이 파일 개수를 0으로 보여줄 때

Synology Drive는 동기화 대상 폴더를 실제로는 `~/Library/CloudStorage/SynologyDrive-작업이름`에 만들고, 사용자가 지정한 경로에는 그곳으로 연결되는 **심볼릭 링크(symlink)**만 놓습니다.

- `find` 명령은 기본적으로 심볼릭 링크를 따라 들어가지 않아서 파일 개수가 0으로 나올 수 있습니다 (버그 아님, `find`의 기본 동작).
- `ls`는 링크를 따라가서 정상적으로 보여줍니다.
- 정확히 세려면 실제 경로를 직접 지정:
  ```bash
  find "/Users/[계정명]/Library/CloudStorage/SynologyDrive-[작업이름]" -type f | wc -l
  ```

### 4-5. 동기화 상태 확인 방법
- Drive Client → **동기화 작업** 목록에서 아이콘 상태 확인
  - 🔄 파란 회전 화살표 = 업로드/동기화 진행 중
  - ✅ 초록 체크 = 완료
  - ⏸ = 일시정지
- 왼쪽 메뉴 **"동기화 로그"**에서 실시간으로 어떤 파일이 올라가는지 확인 가능
- 확실하게 확인하려면 DSM → File Station → 해당 NAS 폴더에서 파일 개수를 직접 세어 로컬과 비교

## 5. 다른 컴퓨터(B) — 보기/수정용 계정 및 연결

### 5-1. B 전용 NAS 계정 만들기 (관리자 계정 공유 금지)

본인(A) 컴퓨터에서 DSM 웹 화면으로 진행합니다.

1. 제어판 → 사용자 및 그룹 → **사용자 추가**
2. 계정명/비밀번호 설정
3. **응용 프로그램 탭** → Synology Drive → **허용** 체크
4. **권한 탭** → `성장전략실/Wiki_시장` 폴더에 대해 **읽기/쓰기** 권한 부여 (B가 직접 수정도 하는 경우)
   - 만약 B가 "보기만" 하는 역할이라면 **읽기 전용**으로 부여
5. 저장

### 5-2. B 컴퓨터에서 진행

1. Synology Drive Client 설치
2. NAS 접속: IP 또는 QuickConnect ID + 방금 만든 B 계정으로 로그인
   - 로그인 안 되면 4-2절의 원인 확인 순서를 동일하게 적용
3. **"동기화 작업"** 선택 (백업 작업 아님)
4. NAS 폴더 선택: "편집" → 팀 폴더 → `성장전략실` → `Wiki_시장` 선택 (이미 있는 폴더를 선택, 새로 만들지 않음)
5. 로컬 폴더 선택: B 컴퓨터의 원하는 위치 지정 (예: `~/Documents/daesan-wiki-local`)
   - ⚠️ 4-3절의 문제가 재발할 수 있으니, **폴더 선택을 마지막 동작으로** 하고 그 이후 다른 필드를 건드리지 않은 상태에서 바로 "완료"
6. 동기화 방향: **양방향** 확인 (B도 수정 가능하게 하려면)
7. 완료 → 초기 다운로드 대기 (전체 파일이 B 컴퓨터로 내려받아짐)

### 5-3. B가 Wiki LLM 앱에서 프로젝트 열기
- 앱 설치 (필요 시)
- "기존 프로젝트 열기" → B 컴퓨터에 동기화된 로컬 경로 지정
- 재인제스트 없이 기존 entity/concept가 그대로 보이면 성공

## 6. 협업 시 반드시 지켜야 할 원칙

### 6-1. 동시 편집 충돌 방지
- **본인(A)이 인제스트를 진행 중일 때는 B가 같은 파일을 수정하지 않는다.**
- 위반 시: Synology Drive가 충돌로 인식해 "(충돌된 사본)" 형태로 별도 파일을 만들어 두 버전이 갈라짐 → 수동 정리 필요

### 6-2. Frontmatter(문서 상단 메타데이터)는 건드리지 않는다

마크다운 파일 맨 위, `---`로 둘러싸인 부분이 frontmatter입니다.

```markdown
---
title: 석고보드
type: entity
sources:
  - naver_blog_001.txt
created: 2026-07-10
---

## 본문 시작
여기부터가 실제 내용
```

- **본문(`---` 아래)** 수정: 안전함. 다음 인제스트/병합 시 이 수정 내용을 기반으로 새 지식이 쌓입니다.
- **frontmatter(`---` 사이) 수정**: 위험함. 앱이 엔티티를 매칭/병합할 때 이 정보를 기준으로 판단하므로, 잘못 건드리면 중복 페이지가 생기거나 오인식될 수 있습니다.

**B에게 전달할 규칙: "본문만 수정하고, 맨 위 `---` 사이 부분은 건드리지 않는다."**

### 6-3. 수정 이력 남기기 (권장)
- B가 수정한 내용은 출처(raw 소스) 근거가 없는 상태로 남습니다. 나중에 "왜 이렇게 바뀌었는지" 추적하기 어려울 수 있으므로, 문서 하단에 간단히 메모를 남기는 걸 권장합니다.
  ```
  <!-- 수정: 홍길동, 2026-07-16, 오탈자 수정 -->
  ```

## 7. 문제 발생 시 체크리스트

| 증상 | 확인할 것 |
|---|---|
| Drive Client 로그인 실패 | DSM 웹 로그인 가능 여부 → 앱 권한 → Drive Server 실행 상태 → 응용 프로그램 서비스 업데이트 → 사용자 홈 서비스 |
| 로컬 폴더 경로에 이름이 자동으로 덧붙음 | "편집" 먼저 → 이름 필드는 마지막에만 손대기, 혹은 mv로 사후 정리 |
| `find` 명령 결과가 0 | 심볼릭 링크 문제일 수 있음 → `~/Library/CloudStorage/SynologyDrive-*` 실제 경로로 직접 확인 |
| 같은 파일이 두 버전으로 갈라짐 | 동시 편집 충돌 → 두 파일 비교 후 수동 병합, 이후 6-1 원칙 재확인 |
| 새 소스 인제스트 후 엔티티가 중복 생성됨 | B가 frontmatter를 건드렸는지 확인 |
